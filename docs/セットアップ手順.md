# セットアップ手順

更新: 2026-09-13。ユーザーの依頼により、現在はCodexが設定・公開を代行しています。**既存の作成済み台帳・GASを使い、新規作成を繰り返さないでください。**

今回の進行状況と本人が行う操作は、ローカルの `.local/本人が行う操作.md` を参照してください。Google承認・台帳・GAS・GitHub Pages公開まで完了し、実送信による台帳保存と自動返信・管理通知の2通を確認済みです。Goopeの案内リンク設置・公開ページからの遷移確認も完了しています。以下は将来別環境を作り直す場合の手動予備手順です。

更新時は `node scripts/deploy-gas.cjs` で同じGASデプロイへ反映します。初回承認後は `node scripts/configure-endpoint.cjs` がGASの準備完了を確認してフォームのURLを設定します。ID等は `.local/deployment.json` に置き、公開リポジトリへ含めません。

## 1. 台帳を作る

1. 通知を管理するGoogleアカウントで Googleスプレッドシートを開き、「空白のスプレッドシート」を作ります。名前を「CCJ 問い合わせリード台帳」にします。
2. 上部の「拡張機能」→「Apps Script」を開きます。
3. 最初からある `myFunction` を含むコードをすべて消し、このフォルダの `google-apps-script.js` の内容をすべて貼り付けます。プロジェクト名を「CCJ 問い合わせ受付」にして保存します。
4. エディタ上部の関数選択で `setupInquiry` を選び、「実行」を押します。自分が作成したスクリプトであることを確かめ、表示される権限確認を進めます。この操作はメールを送信しません。
5. スプレッドシートへ戻り、「リード台帳」タブと32列のヘッダーができたこと、Z列にステータスのプルダウンがあることを確認します。元の空の「シート1」はそのままでも構いません。
6. この操作によりスプレッドシートIDはGASのスクリプトプロパティ `INQUIRY_SPREADSHEET_ID` に自動登録されます。コードへのID貼り付けは不要です。タイムゾーンも日本時間に設定されます。

## 2. GASを公開する

1. Apps Scriptの右上「デプロイ」→「新しいデプロイ」を押します。
2. 種類の選択（歯車）で「ウェブアプリ」を選びます。
3. 説明を「問い合わせ受付 初版」、実行するユーザーを **自分**、アクセスできるユーザーを **全員** にします。ログイン済みユーザー限定にしないでください。
4. 「デプロイ」を押し、必要なアクセス許可を行います。「全員」が選べない場合はアカウントの制限を確認してください。
5. 表示されたウェブアプリのURLをコピーします。末尾が `/exec` のものを使います。`/dev` は使いません。
6. ローカルの `index.html` をテキストエディタで開き、`const SCRIPT_URL = '';` を検索します。引用符の間に、いま発行した問い合わせ用URLを貼り付けて保存します。既存入会フォームのURLは使いません。
7. ブラウザでその `/exec` URLを開き、`result: ready` と表示されることを確認します。これは生存確認であり、台帳保存やメール送信のテストではありません。

## 3. GitHub Pagesを公開する

1. GitHubで `ccjcapoeira` の新しいリポジトリを作り、名前を `ccj-inquiry-form` にします。一般的な無料プランでは Public を選び、READMEの追加などは選ばず空で作ります。
2. ローカルの作業フォルダは `~/GitHub/ccj-inquiry-form` です。初回コミット済みです。GitHub Desktopなら「File → Add Local Repository」でこのフォルダを選び、URL設定の変更をコミットして、作成したリポジトリへ公開・pushします。ターミナルなら次の順です。

   ```bash
   cd ~/GitHub/ccj-inquiry-form
   git add index.html
   git commit -m "問い合わせ用GASのURLを設定"
   git remote add origin https://github.com/ccjcapoeira/ccj-inquiry-form.git
   git push -u origin main
   ```

3. GitHubのリポジトリで「Settings → Pages」を開き、Sourceを「Deploy from a branch」、Branchを `main`、フォルダを `/ (root)` にして保存します。
4. 公開処理が終わったら `https://ccjcapoeira.github.io/ccj-inquiry-form/` を開きます。「プレビュー用フォーム」の表示が消えたことを確認します。
5. 所有者名やリポジトリ名を変える場合は、先に `redirects.json` の `form` と各ドキュメントの公開URLを修正し、`node scripts/build-go.js` で再生成してからpushしてください。

## 4. 公開前の実送信テスト

1. 自分で受信できるメールアドレスを使い、名前欄に「動作確認」と入力してテストします。このリポジトリに個人情報を書き込む必要はありません。
2. `?utm_source=test&utm_medium=qr&utm_campaign=x` を付けてフォームを開きます。一度読み込んだら末尾の `?` 以降を消して再度開き、必要項目を埋めます。
3. キッズを選ぶと年齢が必須になること、その他・紹介を選ぶと補足欄が表示されること、確認画面で戻って編集できることを確認します。
4. 送信後、「リード台帳」に **1行だけ** 増え、ID・日本時間・日本語の選択肢・UTM `test / qr / x` が記録されたことを確認します。
5. 申込者宛の自動返信と、`ccj.osaka@gmail.com` 宛の管理通知の **両方** を確認します。管理通知に受付ID、認知経路、UTMが含まれていることも確認します。
6. スマートフォンでも入力・送信を確認します。検証行はメモを「動作確認」にして集計から除くか、運用開始前に削除します。受付IDは行削除後も現存するIDと重ならないように採番しますが、過去に削除したIDは再利用され得るため、本運用では行を削除しません。
7. テスト用UTMを自分の端末に残したくない場合は、検証専用のプライベートウィンドウを閉じます。通常ブラウザで検証した場合は開発者ツールのサイトストレージから `ccj_attribution` のみ削除します。

**完了画面だけで受付成功とは判断できません。** 指示書指定の `no-cors` 送信はGASの応答を読めません。台帳と2通のメールで実動作を判定してください。

## 5. Goopeからリンクする（ログイン後はCodexで対応可能）

今回の環境では「お問い合わせフォームメッセージ」はHTML非対応でした。以下のデザイン編集で設置済みです。

1. 管理メニュー「デザイン」→適用中デザインの「編集」→「HTML・CSS編集」を開きます。
2. HTMLの `<!-- BEGIN contact -->` から `<!-- END contact -->` までをバックアップします。
3. この区間内の見出しの後、`<form name="frm" method="post" action="{contact_action}" class="contact_form">` の直前に以下のボタンを追加します。既に追加済みなら重ねて追加しません。
4. 保存し、公開ページ `/contact` の表示と新フォームへの遷移を確認します。保存すると即時反映されます。
5. 元に戻す場合は `CCJ inquiry link` の開始・終了コメントとその間だけを削除します。デザイン全体の古いコピーで上書きすると、その後の別の変更も戻るため注意します。

```html
<p><a href="https://ccjcapoeira.github.io/ccj-inquiry-form/"
  style="display:inline-block;background:#185744;color:#fff;padding:14px 20px;border-radius:8px;text-decoration:none;">
  見学・体験のお問い合わせはこちら
</a></p>
```

このリンクは流入元のUTMを書き換えません。Goopeを経由した元のInstagram等のUTMを自動転送する機能は含みません。計測したい広告・QRは新フォームへ直接リンクしてください。詳細は「UTM運用ルール」を参照。

## 6. 更新・困ったとき

- フォームの文言変更: `index.html` を編集→コミット→push。
- QRリンク変更: `redirects.json` を編集→`node scripts/build-go.js`→定義と生成ファイルをコミット→push。
- GAS変更: コードを貼り替えて保存→「デプロイ → デプロイを管理 → 鉛筆 → 新バージョン → デプロイ」。既存デプロイを更新すれば同じURLで使えます。
- 別の台帳へ移す: 新しいシートの拡張機能からGASを作り直し、`setupInquiry` を実行。新デプロイURLをフォームにも設定。
- 台帳に入らない: Apps Scriptの「実行数」で `doPost` のログを確認。`setupInquiry` 未実行、アクセス範囲、URL、ヘッダー変更の有無を確認。
- 台帳にあるのにメールがない: 同じ問い合わせを再送せず、実行ログの受付ID・メール失敗表示を確認。送信上限・権限・迷惑メールを確認し、台帳から手動で返信します。
- 通信エラー後の再送は重複する場合があります。送信中の連打は防ぎますが、別タブや再読み込み後の送信まで重複排除する仕様ではありません。
- 台帳・分析レポートは運営関係者だけに共有します。GitHubには回答データ、台帳ID、台帳の書き出しを追加しません。
