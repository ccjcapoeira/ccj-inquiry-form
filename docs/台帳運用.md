# リード台帳の運用

問い合わせ1件につき1行です。同じ人の再問い合わせも別IDになります。毎営業日、管理通知と新しい行を確認し、2営業日以内に返信します。

## 先生が更新する列

**先生が触る列は「ステータス / 体験日 / 入会日 / 入会理由 / 見送り理由 / メモ」の6列のみです。** 「担当」は指示書のヘッダーに合わせて用意していますが、この版では空欄のままにし、先生は編集しません。担当の連絡事項はメモへ書きます。

| ステータス | 使うタイミング |
|---|---|
| 問合せ | 受付直後。GASが自動設定 |
| 日程調整中 | 返信し、体験等の日程を相談している |
| 体験済 | 実際に体験へ参加した。体験日も入力 |
| 入会 | 入会が確定した。入会日と本人の言葉で入会理由を入力 |
| 見送り | 入会しないと確認できた。見送り理由を入力 |
| 連絡途絶 | 返信がなく、運営で追跡終了と判断した。連絡日と状況をメモ |

## 日々の操作

1. 最新行の希望教室・種別・メッセージを確認し、メールで返信します。予定日時はメモに書き、「日程調整中」へ変更します。
2. 実際に体験したら「体験日」に `2026/10/01` のような日付を入力し、「体験済」へ変更します。**予約日・予定日は体験日列に入れません。** キャンセル・見学だけ・取材は体験済に数えません。
3. 入会確定後に「入会日」と「入会理由」を記入し、「入会」へ変更します。直接入会した場合、体験日は空欄で構いません。
4. 見送りの場合は理由を記録します。推奨選択肢: **時間が合わない / 場所が遠い / 料金 / 子どもが興味を示さなかった / 他の習い事 / 保留 / 連絡途絶 / その他**。詳細はメモへ。見送り理由のプルダウンは必須実装ではなく、必要に応じて管理者がAD列のデータ入力規則へ設定します。
5. ステータスが変わっても、実際の体験日・入会日は消しません。誤記のみ訂正します。日付が空のセルに「未定」「-」などの文字を入れないでください。

## 記録を保つ

- A〜Y列の受付情報・ヘッダー・列順は変更しません。追加列は33列目以降に置きます。先頭32列は位置固定で保存するため、途中への列追加・並べ替えは保存内容のずれにつながります。
- 行を消さず、重複・動作確認はメモへ「集計対象外」と記録し、レポートのフィルタで除外します。動作確認の集計除外も忘れずに行います。
- 並べ替えるならシート全体を対象にします。列1本だけ並べ替えると別人の情報が混ざります。共同作業ではフィルタ表示を使います。
- 日本時間で表示される受付日時はブラウザから届いた送信日時です。IDの日付はGASで受け付けた日の日本時間です。端末時計がずれていると両者が異なる場合があります。
- 自動返信が失敗しても台帳は残ります。GASの実行ログを確認し、台帳から手動返信します。コードによるメール再試行・再送ボタンはありません。
- 氏名・メールを含む台帳やレポートは公開しません。講師の必要な範囲にだけ共有します。

## ヘッダーと列の扱い

**1行目のヘッダーは変更しない。列の追加は33列目以降。** 1〜32列の削除・挿入・並べ替えもしないでください。保存位置は列名に関係なく固定です。ヘッダー名が変わっても受付は継続しますが、管理者へ「【問い合わせ処理エラー】」の警告メールを送ります。列の並べ替えを自動修復する機能はありません。警告を受けたらREADMEの32列対応表で名前・順序を確認してください。

処理例外の通知には取得できた氏名・メール・電話・希望教室を含めます。保存済みの表示がある場合は重複受付を避けて台帳から対応してください。メール送信上限などでエラー通知自体も送れない場合は実行ログだけに残ります。
