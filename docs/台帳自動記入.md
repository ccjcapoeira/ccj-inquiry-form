# 台帳の自動記入（体験日・入会日）

`google-apps-script.js` 末尾の「台帳の自動記入」ブロック。毎朝7時台にトリガーで `syncLedgerEvidence` が動く。

| 項目 | 根拠 | 規則 |
|------|------|------|
| 入会日 | 入会申込シート（`ENROLLMENT_SPREADSHEET_ID`）の「入会申込日」 | 台帳の「メール」と入会シートの「メールアドレス／予備メールアドレス」が一致。問い合わせより1日以上前の申込は既存会員とみなし除外 |
| 体験日 | ccj.osaka@gmail.com の送信済みメール（宛先＝台帳のメール、件名に「体験」と「お礼」） | 件名の「M月D日」を体験日にする。無ければ送信日の前日 |
| ステータス | 上記に伴う | 体験日→「体験済」（問合せ／日程調整中のときのみ）、入会日→「入会」 |

- **空欄だけ埋める。既存の値は上書きしない。** 見送り・連絡途絶・メモに「集計対象外」「動作確認」がある行は対象外
- 記入内容と根拠はシート「自動更新ログ」に残し、変更があった日は管理者へ要約メール
## 見送りの自動化（`syncDeclines`）

| 条件 | 結果 |
|------|------|
| 本人からのメール本文に辞退表現（「今回は見送り」「辞退させて」「検討の結果」など。引用部分は除く） | ステータス「見送り」。理由は本文のキーワードから推定（時間／場所／料金／子どもの興味／他の習い事／保留／その他） |
| 受付日・体験日・最後のメールやり取りのいずれも30日以上前 | ステータス「見送り」・理由「連絡途絶」 |

対象は「問合せ／日程調整中／体験済」の行のみ。理由が既に入っていれば触らない。根拠（メールID・最終更新日）は「自動更新ログ」に残る。

## 外部からの更新API（`ledger_update`）

Claude Code / Cursor が「◯◯さんは見送り」を書き込むための入口。Web アプリの同じ URL に `formType:'ledger_update'` と合言葉（Script Properties `LEDGER_UPDATE_TOKEN`）を付けて POST する。Mac 側のクライアントは vault の `scripts/ledger_update.py`。

- 行の特定: `id`（推奨）／`email`／`name`（部分一致。1件に絞れなければエラーで候補を返す）
- 更新できる項目: `status`・`reason`・`joinReason`・`memo`（追記）は上書き可、`trialDate`・`joinDate` は空欄のみ

## 毎朝の実行順

`dailyLedgerSync` = `syncLedgerEvidence`（体験日・入会日）→ `syncDeclines`（見送り）。トリガーはこの1本。

## 初回セットアップ（Cursor / Codex）

1. `node scripts/deploy-gas.cjs` でコードと権限（gmail.readonly, script.scriptapp）を反映
2. Apps Script エディタで `setEnrollmentSpreadsheetId('<入会申込シートのID>')` を実行（初回は権限承認あり）
3. `issueLedgerUpdateToken` を実行 → ログの合言葉を Mac の `~/Library/Application Support/CCJInquiryLedger/.env` に控える（Git に書かない）
4. `syncLedgerEvidenceDryRun` と `syncDeclinesDryRun` を実行 → 「自動更新ログ」の DRY 行を確認
5. 問題なければ `dailyLedgerSync` を1回手動実行 → 台帳とメールを確認
6. `installLedgerAutoSyncTrigger` を実行（毎朝7時台）
7. Mac で `python3 scripts/ledger_update.py --id <検証行のID> --memo "API疎通確認"` を実行し、台帳のメモに追記されることを確認
